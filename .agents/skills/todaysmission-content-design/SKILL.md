# TODAYSMISSION Content Design Skill

## Pack & Mission Creation Workflow v1.1

## Purpose

This skill defines the complete workflow for designing TODAYSMISSION
Packs and Missions.

The goal is not to generate large quantities of challenges.

The goal is to create:

-   psychologically meaningful Packs
-   behavior-focused Missions
-   realistic executable tasks
-   content with clear user value
-   structured experiences that can produce real-world behavior change

A Pack is not a topic collection.

A Pack is:

> A curated behavioral training space targeting one specific avoidance
> pattern.

------------------------------------------------------------------------

# Part 1 --- Pack Design Workflow

## Step 1: Identify the Real User Problem

Never start from a theme.

Bad:

-   Confidence Pack
-   Become Better Socially
-   Self Improvement Pack

These are too broad.

Start from:

> What specific behavior is the user avoiding?

A valid Pack requires:

    Fear / discomfort
            ↓
    Avoided behavior
            ↓
    Negative reinforcement loop
            ↓
    Target behavior to rebuild

Example:

    Fear:
    Nobody will come with me.

    Avoidance:
    I stop doing activities I want.

    Loop:
    No companion → cancel → never gain experience.

    Target:
    Independent action.

------------------------------------------------------------------------

# Step 2: Define Pack Identity

Before creating Missions, define:

## Core Problem

What pain does this Pack solve?

## Core Avoidance Pattern

What does the user repeatedly avoid?

## Training Goal

What new behavior should the user gain?

## Pack Boundary

What belongs?

What does NOT belong?

A Pack without boundaries will become a random challenge list.

------------------------------------------------------------------------

# Step 3: Validate Pack Quality

A Pack should pass:

## User Recognition Test

Would users immediately think:

> "This is exactly my problem."

## Behavior Test

Can the problem be represented by observable actions?

Avoid:

-   become confident
-   think positively
-   love yourself

Prefer:

-   go somewhere alone
-   ask for something
-   start a conversation

## Mission Generation Test

Can we create enough genuinely different Missions to form a balanced
training space?

There is no fixed or minimum Mission count.

The number must come from the Pack's actual behavioral training space,
after overlap, repetition, executability, and safety review.

Every Pack must contain fewer than 25 Missions in total, including any
hidden Final Mission.

Never keep, split, or invent Missions just to reach a preferred count.

If only a smaller number of Missions have distinct learning value, use
the smaller number. If that smaller pool cannot form a meaningful and
balanced training space, redefine or reject the Pack instead of filling
the gap with weak Missions.

## Overlap Test

Would this Pack heavily overlap with another Pack?

If yes, redefine the boundary.

------------------------------------------------------------------------

# Part 2 --- Mission Design Workflow

## Step 1: Define Mission Learning Objective

Every Mission must answer:

> What psychological barrier does this train?

A Mission is invalid if the answer is unclear.

Example:

Bad:

"Go outside."

No clear target.

Good:

"Spend 20 minutes alone in a busy public place."

Target:

"Being visible while alone."

------------------------------------------------------------------------

# Step 2: Define Primary Training Variable

Every Mission should have one main purpose.

Possible variables:

-   public visibility
-   uncertainty
-   social exposure
-   duration
-   independence
-   rejection possibility
-   commitment
-   personal importance

Do not make one Mission train everything.

------------------------------------------------------------------------

# Step 3: Build Difficulty Space

Difficulty should not only be Level 1--10.

Analyze multiple dimensions.

Recommended fields:

    public_visibility
    duration
    cost
    location_dependency
    facility_dependency
    social_exposure
    interaction_required
    uncertainty
    default_companion_expectation
    personal_importance

A Mission can be difficult because:

-   many people are watching
-   it lasts a long time
-   it feels socially unusual
-   the result is uncertain
-   the user personally cares about the outcome

------------------------------------------------------------------------

# Step 4: Ensure Real-World Executability

Before adding a Mission, check:

## Location

Can users in:

-   large cities
-   small cities
-   rural areas
-   schools
-   workplaces

complete it?

## Cost

Does it require money?

If yes:

-   Is there a free alternative?
-   Is the Pack too dependent on spending?

## Facilities

Does it require:

-   cinema
-   cafe
-   museum
-   special venue

If yes:

The behavior should be the Mission, not the location.

Example:

Bad:

"Go bowling alone."

Better:

"Do a recreational activity people usually do with friends, alone."

------------------------------------------------------------------------

# Step 5: Separate Behavior From Example

A Mission defines behavior.

Examples only help users understand.

Structure:

    Mission:
    Do X behavior.

    Examples:
    A / B / C possible ways.

Never create Missions that only work in one environment.

------------------------------------------------------------------------

# Part 3 --- Mission Pool Design

A good Pack should not be:

20 random tasks.

It should be a balanced space.

## Mission Count

Mission count is an output of the design process, not an input.

First map the Pack's training dimensions. Then generate, review, merge,
and reject candidates. Set the final count only after every remaining
Mission has a distinct learning objective and the pool has adequate
difficulty coverage.

Rules:

-   No fixed count.
-   No minimum count.
-   Fewer than 25 Missions per Pack in total, including any hidden Final
    Mission.
-   Do not copy the Mission count of another Pack.
-   Do not split one behavior across locations, objects, audiences, or
    wording merely to increase the count.
-   A smaller strong pool is preferable to a larger repetitive pool.

Required coverage:

## Low Barrier

Tasks users can start with.

Purpose:

Reduce activation energy.

## Medium Discomfort

Tasks where users notice discomfort but can complete.

Purpose:

Build confidence through experience.

## High Challenge

Tasks with:

-   high visibility
-   strong social expectations
-   meaningful personal discomfort

Purpose:

Create transformation moments.

------------------------------------------------------------------------

# Part 4 --- User Choice Model

TODAYSMISSION uses:

## Pack Membership + Free Pick

Users join the entire Pack, not individual Missions.

Flow:

    Browse public Pack content
             ↓
    Join the Pack
             ↓
    Freely choose or switch Missions
             ↓
    Complete a Mission through the real completion flow
             ↓
    Pack progress updates

Do NOT reintroduce a per-Mission Take or Lock step.

Switching the currently viewed Mission does not:

-   join the Pack
-   complete a Mission
-   change completion records
-   force a sequence

Do NOT force:

Mission 1 → Mission 2 → Mission 3

Reason:

Users have different fear structures and different real-world conditions
on a given day.

However:

The Mission Pool must contain a clear challenge gradient.

Freedom does not mean removing difficulty.

------------------------------------------------------------------------

# Part 5 --- Hidden Final Mission Design

Every Pack may contain a final hidden Mission.

Purpose:

Move from training environment to real life.

Structure:

    Complete all public Missions
            ↓
    Unlock Final Mission
            ↓
    Apply skill to personal life

Final Mission should NOT be another generic challenge.

It should answer:

> "What has this user actually been avoiding?"

Examples:

Doing Things Alone:

"Do the thing you've been waiting for someone else to do with you."

Fear of Rejection:

"Ask for something you genuinely want, even if the answer may be no."

Talking to Strangers:

"Start a meaningful interaction you have always avoided."

------------------------------------------------------------------------

# Part 6 --- Mission Review Checklist

Before approving a Mission:

## Problem Fit

□ Does it belong to this Pack?

□ Is the psychological barrier clear?

## Behavior

□ Is there a real action?

□ Can completion be objectively judged?

## User Control

□ Is success determined mainly by the user's action?

□ Is it unfairly dependent on another person's reaction?

## Reality

□ Can users realistically complete it?

□ Does it require unavailable facilities?

□ Does it create unnecessary cost?

## Safety

□ Does it respect other people's boundaries?

□ Does it avoid harassment or inappropriate behavior?

## Uniqueness

□ Is it meaningfully different from existing Missions?

------------------------------------------------------------------------

# Part 7 --- Things To Avoid

## Generic Self-help Tasks

Avoid:

-   write positive affirmations
-   think about your strengths
-   love yourself
-   become confident

Unless they directly connect to behavior.

------------------------------------------------------------------------

## Artificial Challenges

Avoid:

-   intentionally embarrassing strangers
-   meaningless discomfort
-   tasks designed only to create difficulty

Challenge should come from real life.

------------------------------------------------------------------------

## Quantity Filling

Never create Missions because:

"We need 20 cards."

A smaller set of strong Missions is better.

------------------------------------------------------------------------

# Part 8 --- Artwork Production Handoff

When the deliverable is a final or approved Pack specification intended
to supply downstream artwork production, append the structured handoff
defined in [references/artwork-handoff-schema.md](references/artwork-handoff-schema.md).

The handoff supplies behavioral truth and a flexible semantic vocabulary.
It must not turn each Mission into a prescribed literal scene. Record the
exact action, learning objective, usable action/prop/environment/relationship/
symbolic anchors, confusion risks, safety exclusions, and whether direct,
associative, or free treatment is semantically safe.

Mission Artwork is a post-completion collectible reward. Do not frame it as
the user's pre-task fear, and do not require it to reenact the Mission. The
downstream artwork system owns semantic-distance planning, expression,
acting, camera, palette, composition, character casting, and collection
diversity.

For Pack Cover, provide Pack-level experience clusters and a grounded pool of
content tokens drawn from actual Missions. Describe semantic range, not a
single scene. The artwork system selects and integrates a limited set and
generates the Cover after Mission art establishes the collection vocabulary.
Frontend text is not part of the artwork.

The handoff does not authorize image generation, publishing, code changes,
or asset replacement.

Do not add the handoff to early ideation unless the user requests it.

------------------------------------------------------------------------

# Part 9 --- Final Standard

A high-quality TODAYSMISSION Pack should achieve:

1.  User immediately recognizes the problem.
2.  Every Mission has a clear behavioral purpose.
3.  Tasks are realistic worldwide.
4.  Difficulty has range without forcing order.
5.  Completion creates a real experience.
6.  Final Mission connects training to real life.

The question is never:

> "Is this challenge interesting?"

The correct question is:

> "If a user completes this, what changes about their future behavior?"
