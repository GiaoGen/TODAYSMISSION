# TODAYSMISSION Canonical Model Style Lock

Version: 1.0
Status: LOCKED
Style Master: Character 01 — Dinosaur Canonical Model

## Purpose

This file defines the shared rendering and finish standard for all TODAYSMISSION character canonical assets.

It answers:

> Do these characters look like they belong to the same visual system?

It does **not** define any individual character's identity. Individual identity is defined by each character's `character-lock.md`.

---

## 1. Rendering Direction

TODAYSMISSION uses a **refined hand-drawn 2D animation** rendering language.

Target balance:

- clearly hand-drawn
- clean and production-ready
- subtle natural imperfection
- not raw sketch
- not perfect vector
- not glossy mascot rendering

Approximate hand-drawn roughness scale:

- `0` = perfect vector geometry
- `10` = raw pencil sketch
- TODAYSMISSION Canonical target = approximately **3.5–4 / 10**

The approved Dinosaur Canonical Model is the visual finish master.

---

## 2. Linework

Required:

- clean hand-drawn contour
- slight natural variation in line weight
- minimal wobble
- no repeated scratchy tracing
- outer contour may be slightly stronger than internal detail
- dark desaturated character-compatible line color rather than harsh uniform pure black when appropriate

Avoid:

- raw pencil messiness
- thick uniform vector outlines
- overly rough or fuzzy contour
- photorealistic edge rendering

---

## 3. Color & Surface

Required:

- matte dominant color blocks
- color shape is primary
- texture is secondary
- restrained dry-pencil / paper texture visible mainly on close inspection
- minimal tonal variation
- subtle cel-like volume only

Avoid:

- glossy highlights
- airbrushed synthetic gradients
- plastic toy surfaces
- heavy watercolor wash
- realistic fur / feather rendering
- texture becoming the dominant visual feature

Core principle:

> Texture is secondary; clean color shape is primary.

---

## 4. Canonical Sheet Finish

All Canonical Models should feel like pages from the same professional character bible.

Shared expectations:

- warm off-white / cream sheet background
- clear turnaround views
- detail callouts
- proportion reference
- color palette section
- line / texture section
- expression examples
- similar information hierarchy
- generous negative space
- refined hand-drawn finish

Layout may vary slightly, but finish level must remain consistent.

---

## 5. Acting Stress Test Finish

Acting Stress Tests may be more scene-oriented than Canonical Models, but they must preserve the same core rendering language.

Allowed:

- stronger pose deformation
- props and clothing
- environmental scenes
- more expressive asymmetry
- different camera directions

Not allowed:

- redesigning the character
- switching rendering style
- increasing roughness dramatically
- realistic fur / feather treatment
- using the stress test as a new identity source

---

## 6. Authority Hierarchy

For each character:

1. `canonical-model.png` — visual identity source of truth
2. `character-lock.md` — textual identity source of truth
3. approved production artwork — precedent only
4. `acting-stress-test.png` — evidence of allowable elasticity
5. `prompt-fragment.md` — compressed production instruction derived from the lock

If the Prompt Fragment conflicts with the Character Lock, the Character Lock wins.

If generated artwork conflicts with the Canonical Model, the Canonical Model wins.

---

## 7. Global Principle

The seven characters share the same **drawing language**, not the same face.

Do not force identical:

- eye architecture
- nose structure
- mouth structure
- face markings
- proportions

Do preserve shared:

- simplified rounded design language
- refined hand-drawn finish
- matte color treatment
- controlled texture
- animation-friendly elasticity
- warm approachable tone

---

## 8. Audit Rule

A Canonical Audit must inspect existing approved assets.

Do **not** regenerate all seven characters in one new lineup to perform an audit.

Regenerating a multi-character summary can cause cross-character contamination and identity averaging.

Audit existing Canonical Models instead.
